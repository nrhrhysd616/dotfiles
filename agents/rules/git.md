# Git規約

プロジェクトに独自の規約がある場合はそちらを優先する。

## コミットメッセージ

**Conventional Commits** 形式:

```txt
<type>(<scope>): <subject>

<body>

<footer>
```

**Type:**

- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメント変更
- `style`: デザイン修正
- `refactor`: リファクタリング
- `perf`: パフォーマンス改善
- `test`: テスト追加・修正
- `chore`: ビルドプロセスやツール変更

## コミットとPRの粒度

- 段階的に進む作業は**コミットを分け、PRは1つにまとめる**。
  PR作成には都度ユーザーの許可が要るため、複数PRは手間が増える。
  「段階ごとに別PR」を選択肢として出さない
- 段階の切れ目はコミット境界で表現し、各コミットの前に検証を通して
  レビュー時に追えるようにする
- ブランチは分けてよい。「下ごしらえのリファクタ → 本題」の2段構えなら、
  **後続ブランチを前段ブランチの先端から生やす**（ベースブランチから独立に生やさない）。
  最終的なPRは後続ブランチ → ベースブランチの1本で、前段のコミットもそこに含まれる。
  計画時にブランチ名と分岐元を明示する
